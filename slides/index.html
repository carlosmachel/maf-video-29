01 · gancho

Quantas vezes um agente
parou no meio da tarefa?

Ou "esqueceu" o que já tinha feito assim que você chamou de novo. Hoje vamos ver por quê — e três formas de resolver isso, em camadas.

o cenário

Um Analista de Vendas com dados de receita mensal. O mesmo agente de negócio nas 3 demos — só a camada em volta dele muda.

a pergunta que guia tudo

Todo agente que faz algo de verdade é, por baixo, um loop. O quanto desse loop você controla é o que muda entre as camadas.

03 · demo 1 — agent simples

Agente tem tools. Executa num loop.

prompt → modelo decide → chama tool → tool responde

↺ repete até não sobrar tool call — só então responde

Program.cs
// client: AIProjectClient (Azure.AI.Projects)
AIAgent agent = client.AsAIAgent(
    deploymentName,
    name: "AnalistaDeVendas",
    tools:
    [
        AIFunctionFactory.Create(SalesTools.GetRevenue),
        AIFunctionFactory.Create(SalesTools.CompareRevenue),
    ]);

await agent.RunAsync("Compare, planeje e salve em .md");

funciona

Pergunta única — o loop de tools resolve sozinho.

não existe

Plano, arquivo em disco, memória entre execuções.

03 · demo 2 — agent + harness

Mesmo agente. Loop por fora.

loop do harness
plano → todo-list → executa passo → verifica
loop do agente
modelo ⇄ tools

↺ repete até a todo-list fechar

Program.cs
AIAgent agent = client
    .GetProjectOpenAIClient().GetResponsesClient()
    .AsIChatClient().AsHarnessAgent(new HarnessAgentOptions
    {
        ChatOptions = new() { ModelId = deploymentName },
        FileAccessStore = new FileSystemAgentFileStore(outputDir),
    });
await agent.RunStreamingAsync(input, session);

03 · demo 3 — loop engineering

Você decide o que significa "terminado".

loop do juiz
loop do agente
modelo ⇄ tools
rascunho → juiz avalia critérios

↺ reprovado → feedback → nova tentativa (máx. 3×)

Program.cs
// workerAgent: o mesmo client.AsAIAgent(...) da demo 1
string[] criteria =
[
    "Tabela markdown comparando os meses",
    "Secao 'Riscos' com 2+ itens",
    "Recomendacao de acao clara",
];
var judge = new AIJudgeLoopEvaluator(judgeClient, new() { Criteria = criteria });

AIAgent loopedAgent = new LoopAgent(workerAgent, judge,
    new LoopAgentOptions { MaxIterations = 3 });

não é prompt engineering

São critérios de aceite — tipo um teste automatizado pra texto.

trava de segurança

Loop julgado por IA custa tempo e dinheiro. Sempre tenha um teto.

03 · demo 4 — workflow (multi-agente)

As 3 anteriores giram em torno de UM agente. Essa troca de eixo.

grafo do workflow
pergunta → Coordenador

fan-out — os dois rodam em paralelo

AnalistaFinanceiro AnalistaDeProduto

fan-in barrier — só segue quando os dois terminarem

Redator → relatorio-workflow.md
Program.cs
// coordenador, analistaFinanceiro, analistaDeProduto e redatorAgent já existem
Workflow workflow = new WorkflowBuilder(coordenador)
    .AddFanOutEdge(coordenador, [analistaFinanceiro, analistaDeProduto])
    .AddFanInBarrierEdge([analistaFinanceiro, analistaDeProduto], redator)
    .WithOutputFrom(redator)
    .Build();

await using StreamingRun run =
    await InProcessExecution.RunStreamingAsync(workflow, pergunta);

outro eixo

Não é mais controle sobre UM agente — é orquestração explícita entre vários.

cuidado

O fan-in barrier espera todos os ramos — um agente travado trava o grafo inteiro.
